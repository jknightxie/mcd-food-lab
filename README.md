## 为什么是「每元」，不是「大卡」

营养表给你一堆绝对值，但选择发生在相对之间：391 和 513 大卡，对你意味着什么？
这个 391 大卡花 23 块买到，值吗？——**营养表不回答这些问题。**

「每元效率」给了参照系：**预算**。你掏出 25 块的时候，这个数字是确定的。

除下去的结果（实测，非示例）：

| 餐品 | 蛋白质 | 价格 | **蛋白质/元** |
|---|---:|---:|---:|
| **那么大鸡排（椒盐风味）** | 24 g | ¥14.0 | **1.71** |
| 双层吉士汉堡 | 27 g | ¥23.0 | 1.17 |
| 巨无霸 | 27 g | ¥25.5 | 1.06 |
| 板烧鸡腿堡 | 23 g | ¥23.5 | 0.98 |

> **巨无霸不是麦当劳蛋白质性价比最高的汉堡。**
> 14 元的那么大鸡排才是——每元高 61%，还便宜 11 块。

## 先问一句，再给答案

营养指标没有绝对最优，只有**对你的目标最优**。所以它先问「今天这顿想干什么？」
（问完就停，不摆选项——选项会限制表达）。它听懂的是你的说法，不是标签：

| 你可能会说 | 它理解成 | 排序依据 |
|---|---|---|
| 随便吃点 / 想吃点好的 | 解馋 | 热量/元↓，蛋白质 ≥0.4 |
| 今天想控制一下 | 管住嘴 | 蛋白质/元 ↑ |
| 招待朋友 / 同事聚餐 | 请客 | 价格↑（排面优先），蛋白质 ≥0.8 |
| 带小孩来 | 给小孩 | 钙/元↑，蛋白质 ≥0.5 |
| 刚练完 / 增肌期 | 今天在练 | 蛋白质/元 ↑ + 钠·脂肪 |
| **累死了 / 心情不好** | **犒劳自己** | **供能密度 ↑**（越高越好） |

两个反直觉的设计：

- **请客不为性价比买单**——按价格档位选「拿得出手」的（安格斯系霸榜），
  守卫挡住撑不住场面的，每元效率降级为参考
- **疲惫时推低热量是反的**——那会让你更没力气，所以「犒劳自己」按供能密度排

**六个场景冠军各不相同。** 如果六个场景推同一款，这一问就是装饰品。

## 两个实测发现（也是为什么必须实时查）

我们在**北上广深四城、七家门店**重跑了同一套计算：

| 城市 | 门店 | 在售 | 营养库覆盖 |
|---|---|---:|---:|
| 北京 | 建外 SOHO | 104 | 19% |
| 上海 | 吴江路 | 73 | **21%** |
| 上海 | 静安锦沧文华 | 100 | 20% |
| 广州 | 天源路 | 116 | 19% |
| 广州 | 长兴路 | 119 | **18%** |
| 深圳 | 福田高铁站 | 103 | **18%** |
| 深圳 | 领展中心城 | 103 | 19% |

**① 覆盖率是结构性缺口，不是某家店数据不全。** 门店规模差了近一倍（73 vs 119 款），
覆盖率却稳定在 18%~21%。而且没查到的 84 款里恰好包含几乎全部甜品——朱古力新地、
麦旋风、香芋派都在菜单上、都能点，但营养库里没有。推荐里看不到它们，
**不是我们拦着，是麦当劳没给数据**。我们把这件事放在第一屏：营养标注不完整的餐品，
恰恰最不该被推荐给在意营养的人。

**② 同一个巨无霸，四城价格不同。** 北上广 ¥25.5，深圳 ¥26.5——1 块差价让每元蛋白
从 1.06 掉到 1.02，排名掉一名。7 家门店里没有一家是巨无霸第一。

所以这个工具不预置任何「麦当劳营养表/价格表」，**每次现查现算**。

## 我们做对了什么别人没做的

| 常见做法 | 我们的做法 | 差别 |
|---|---|---|
| 给一份「健康推荐」榜单 | 先问场景再排序（六场景六套标准） | 同一个巨无霸，六个场景六个答案 |
| 只给营养，不给价格 | 所有指标**除以价格** | 总量会骗人，每元不会 |
| 覆盖率不足就估算补齐 | 查不到就明说不参与，19% 也放第一屏 | 宁可少报，不可编造 |
| 推荐完就结束 | 推荐 → 卡片 → 点餐单 → 确认下单回支付链接 | 从「看」到「点」闭环 |
| 预置菜单/价格快照 | 每次实时查（四城差价实测） | 门店错了结论就是错的 |
| 结果是一张表格 | 值得晒的卡（四风格切换 + 段位战报 + 水印图章） | 传播是设计出来的 |

<div align="center">

> **差异化内核：别处告诉你「吃什么健康」，我们告诉你「每一块钱买到多少营养」——
> 而且敢把没查到的 81% 放在第一屏。**

## 三条底线

**① 查不到就说查不到。** 没有数据的餐品不猜、不估、不填，直接不进推荐，并告诉你少了什么。

**② 异常值原样输出，只标注。** 实测某牛堡标注 1003 大卡（同类 696~707），我们不知道
这个值是不是错的，所以只标一句「建议以实际包装为准」，不删也不改。

**③ 一个数字都不编。** 所有比值来自官方接口实测值，缺失值显示 `—`，
**绝不当作 0 参与排序**——那是撒谎。

## 快速开始

**① 连麦当劳 MCP（一次）** —— 复制配置合并进你的 MCP 设置：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer 你的Token" }
    }
  }
}
```

Token：`https://mcp.mcd.cn` → 手机号登录 → 控制台激活。Skill 会自动从这个配置读 Token。

**② 装成 Skill** —— WorkBuddy 放到 `~/.workbuddy/skills/mcd-food-lab/`，
Claude Code 放到 `~/.claude/skills/mcd-food-lab/`。

**③ 直接说话** —— 不用重启，不用敲命令。门店不用你查：说「我在国贸」它会自己定位；
没说位置它会反问一句（有意如此：实测同一巨无霸北上广 ¥25.5、深圳 ¥26.5，
门店不问清，答案就是错的）。

| 你想干什么 | 你只要说 |
|---|---|
| 想玩 | 「考考我」 |
| 不知道选哪款 | 「今天中午吃麦当劳，帮我挑一款」 |
| 有具体目标 | 「我刚练完，能吃点什么」「带小孩，点什么好」 |
| 直接问指标 | 「哪款蛋白质性价比最高」「哪款最补钙」 |
| 想点单 | 「就它了，鸡排来一份加两盒牛奶」 |

## 技术实现

```
Skill 编排层（SKILL.md：问场景 → 定门店 → 调工具 → 算 → 呈现）
    │
    ├─ list-nutrition-foods   全国固定营养库（160 项）
    ├─ query-meals            门店实时菜单 + 价格
    ├─ calculate-price        实时计价（点餐单）
    └─ create-order           真实下单（写操作，用户明确二次确认才碰）
    │
    ▼
scripts/mcd_client.py    JSON-RPC + SSE 解析，纯适配层
scripts/fuel_index.py    纯函数：每元效率 + 场景推荐（零网络请求，可离线测试）
scripts/quiz.py          战力测试：实时数据出题 + 50 梗壳随机套用 + 段位
scripts/order.py         点餐单：计价 / 下单回执 / 退单
scripts/card.py          四套风格可分享卡片（推荐 / 战报 / 点餐单）
```

`fuel_index.py` 里没有一个网络调用——**254 项测试不需要 Token 即可运行**，
所有 fixture 都来自真实 MCP 响应。

接口上的怪癖（营养库返回的不是 JSON、没有 `sugar` 字段、名字匹配要两级）、
以及 10+ 条官方文档没写明的调用契约，全部记在
[`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md)。其中一条值得单独说：

> **含糖量算不了。** 官方只给 `carbohydrate`（碳水 ≠ 糖，淀粉也算碳水），
> 所以这个工具不显示「糖」，也不假装能算。
